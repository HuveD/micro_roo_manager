## 검토 범위

1. **프로젝트 규칙 검증**
   - **아키텍처 일치성**: 기존 프로젝트 아키텍처 패턴과 설계 원칙 준수
   - **코딩 컨벤션**: 프로젝트 전체 코딩 스타일 및 네이밍 규칙 일관성
   - **코드베이스 통일성**: 기존 코드와 구조적 일관성 유지

2. **작업 완료성 검증** 
   - **변경 누락 검사**: 기존 로직 변경 시 연관된 모든 코드 변경 완료 확인
   - **의존성 체크**: 변경된 코드를 사용하는 모든 위치 수정 확인
   - **계획 실행 검증** (plan-output.md 존재시): TODO 완료 상태
   - **부분 작업 방지**: 미완성 기능이 배포되지 않도록 검증

3. **사이드 이펙트 분석**
   - **git diff 심층 분석**: 변경사항이 미칠 영향 범위 파악
   - **기존 기능 영향도**: 변경으로 인한 기존 기능 손상 가능성 검토
   - **API 호환성**: 외부 인터페이스 변경사항 검증
   - **데이터 무결성**: 스키마/데이터 변경의 부작용 확인

4. **단일 책임 원칙 검증**
   - **파일 책임**: 각 파일은 하나의 도메인/기능만 담당
   - **클래스 책임**: 각 클래스는 하나의 변경 이유만 존재
   - **메서드 책임**: 각 메서드는 하나의 명확한 작업만 수행
   - **책임 분산**: 과도한 책임을 가진 컴포넌트 식별 및 분리 필요성 검토

5. **코드 품질 검증**
   - **크기 제한**: 파일 500줄, 메서드 15줄 (문서 제외)
   - **중복 제거**: 동일 로직 재사용
   - **설계 원칙**: SOLID, DRY, KISS

6. **문서-코드 동기화** (docs/ 존재시)
   - interfaces: API 명세 ↔ 실제 구현
   - design: 설계 원칙 ↔ 코드 구조
   - logic: 비즈니스 규칙 ↔ 도메인 코드
   - standards: 코딩 표준 ↔ 코드 품질


## 작업 타입별 핵심 검증

- **핫픽스**: 최소 수정, 회귀 테스트
- **기능 추가**: 요구사항 충족, 기존 기능 영향 없음
- **아키텍처 변경**: 설계 문서 일치, 단계별 구현
- **표준 구축**: 실용성, 팀 적용 가능성
- **리팩토링**: 동작 보존, 품질 개선
