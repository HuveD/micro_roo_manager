## 검토 프로세스

### 1. 계획 대비 실행 검증
plan-output.md를 읽어서 다음을 확인하세요:
- 모든 TODO가 완료되었는지 확인
- 계획된 문서가 실제로 작성되었는지 확인
- 작업 기록의 일관성 검증

### 2. 지속적 가치 문서와 코드 일치성 검토

**인터페이스 계약** (docs/interfaces/ ↔ 실제 인터페이스) *존재시만*:
- API 명세가 실제 구현과 일치하는지 검증
- 데이터 스키마가 정확히 구현되었는지 확인
- 에러 처리가 명세대로 되었는지 검증

**설계 준수** (docs/design/ ↔ 코드 구조) *존재시만*:
- 설계 원칙이 코드에 준수되었는지 검증
- 모듈/컴포넌트 구조가 설계와 일치하는지 확인
- 의존성 관계가 설계대로 구현되었는지 검증

**비즈니스 로직** (docs/logic/ ↔ 도메인 코드) *존재시만*:
- 비즈니스 규칙이 정확히 구현되었는지 검증
- 도메인 개념이 코드에 명확히 표현되었는지 확인
- 상태 변화와 생명주기가 올바른지 검증

**표준 준수** (docs/standards/ ↔ 코드 품질) *존재시만*:
- 코딩 컨벤션이 정확히 적용되었는지 검증
- UI/UX 가이드가 일관되게 구현되었는지 확인
- 로깅 가이드가 올바르게 적용되었는지 검증

### 3. 코드 품질 분석

**테스트 품질**:
- 테스트 커버리지 확인
- 테스트가 요구사항을 충분히 검증하는지 확인
- Edge case와 예외 상황 테스트 여부 확인

**코드 스타일과 일관성**:
- 프로젝트 코딩 컨벤션 준수 여부
- 네이밍 일관성
- 코드 중복 여부

**설계 원칙**:
- **단일 책임 원칙(SRP)**: 파일, 클래스, 메서드가 각각 하나의 역할만 수행하는지 검증.
  - 파일 크기가 500라인을 초과하는 경우 단일 책임 원칙 위반 가능성 체크 (문서 파일은 검토 제외)
  - 메서드가 10줄을 초과하는 경우 분할 필요성 검토
- SOLID 원칙 전체 준수 여부
- DRY 원칙 준수 여부  
- KISS 원칙 준수 여부

**보안 및 성능**:
- 보안 취약점 존재 여부
- 성능 병목 지점 존재 여부
- 리소스 관리 적절성

### 4. 작업 타입별 최적화 검증

plan-output.md의 "작업 타입"을 확인하고 해당 타입별 검증을 수행하세요:

**핫픽스/버그 수정 검증**:
- 버그가 정확히 수정되었는지 확인
- 회귀 테스트가 추가되었는지 검증
- 수정 범위가 최소한인지 확인

**단순 기능 추가 검증**:
- 기능이 요구사항대로 구현되었는지 확인
- 기존 기능에 영향이 없는지 검증
- 통합 테스트가 적절한지 확인

**아키텍처/복잡한 변경 검증**:
- 설계 문서와 구현이 일치하는지 검증
- 아키텍처 원칙이 준수되었는지 확인
- 단계별 구현이 체계적인지 검증

**표준/가이드라인 구축 검증**:
- 표준 문서가 명확하고 실용적인지 확인
- 표준이 실제 코드에 적용되었는지 검증
- 팀 적용 가능성이 높은지 평가

**리팩토링 검증**:
- 기존 동작이 보존되었는지 확인
- 코드 품질이 실제로 개선되었는지 검증
- 회귀 테스트가 모두 통과하는지 확인

- 표준 준수: [점수]/10 (standards 적용시)

### 핵심 피드백
