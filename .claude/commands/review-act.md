## 검토 프로세스

### 1. 계획 대비 실행 검증
plan-output.md를 읽어서 다음을 확인하세요:
- 모든 TODO가 완료되었는지 확인
- 계획된 문서가 실제로 작성되었는지 확인
- 작업 기록의 일관성 검증

### 2. 문서와 코드 일치성 검토

**요구사항 추적** (docs/requirements/ ↔ 구현):
- 모든 요구사항이 코드에 반영되었는지 검증
- 불필요한 기능이 추가되지 않았는지 확인
- 요구사항 변경 사항이 문서에 반영되었는지 확인

**설계 준수** (docs/design/ ↔ 코드 구조):
- 설계 원칙이 코드에 준수되었는지 검증
- 모듈/컴포넌트 구조가 설계와 일치하는지 확인
- 의존성 관계가 설계대로 구현되었는지 검증

**인터페이스 계약** (docs/interfaces/ ↔ 실제 인터페이스):
- API 명세가 실제 구현과 일치하는지 검증
- 데이터 스키마가 정확히 구현되었는지 확인
- 에러 처리가 명세대로 되었는지 검증

**비즈니스 로직** (docs/logic/ ↔ 도메인 코드):
- 비즈니스 규칙이 정확히 구현되었는지 검증
- 도메인 개념이 코드에 명확히 표현되었는지 확인
- 상태 변화와 생명주기가 올바른지 검증

### 3. 코드 품질 분석

**테스트 품질**:
- 테스트 커버리지 확인
- 테스트가 요구사항을 충분히 검증하는지 확인
- Edge case와 예외 상황 테스트 여부 확인

**코드 스타일과 일관성**:
- 프로젝트 코딩 컨벤션 준수 여부
- 네이밍 일관성
- 코드 중복 여부

**설계 원칙**:
- SOLID 원칙 준수 여부
- DRY 원칙 준수 여부
- KISS 원칙 준수 여부

**보안 및 성능**:
- 보안 취약점 존재 여부
- 성능 병목 지점 존재 여부
- 리소스 관리 적절성

### 4. Universal Document-Driven TDD 검증

**TDD 프로세스 준수**:
- 테스트가 구현보다 먼저 작성되었는지 확인
- Red-Green-Refactor 사이클이 지켜졌는지 검증
- 최소 구현 원칙이 지켜졌는지 확인

**문서 주도 개발**:
- 문서가 코드보다 먼저 작성/업데이트되었는지 확인
- 문서가 Single Source of Truth 역할을 하는지 검증
- 문서와 코드가 동기화되어 있는지 확인
