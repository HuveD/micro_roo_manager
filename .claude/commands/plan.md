## [테스트] 테스트 전략 (Pragmatic TDD)

### 테스트 필요성 평가 기준
```
테스트 가치 = (복잡도 × 비즈니스 중요도) / 유지보수 비용
(개념적 공식: 핵심 로직 위주로 테스트 작성, 과도한 테스트 지양)

[O] TDD 필수 (높은 ROI)
  - 핵심 비즈니스: 가격계산, 권한검증, 결제처리
  - 복잡한 알고리즘: 데이터변환, 검색/필터, 상태기계
  - 외부 통합: API 클라이언트, 외부서비스 (Mock 필수)

[X] 테스트 제외 (낮은 ROI)
  - 단순 로직: getter/setter, CRUD, DTO 매핑
  - UI/프레임워크: 라우팅, 렌더링, 기본 기능
```
