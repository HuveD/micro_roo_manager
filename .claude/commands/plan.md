# ClaudeCode 스마트 계획 수립 명령어

ultrathink, 지금까지 논의된 사항을 분석하여 상세한 실행 계획을 수립하세요.

## 1. 기존 계획 확인

먼저 plan-output.md 존재 여부를 확인하고 다음 규칙을 따르세요:

| 상황 | 액션 |
|------|------|
| plan-output.md 있음 + 미완료 TODO 존재 | "기존 TODO를 먼저 act 명령으로 완료하세요" 응답 후 중단 |
| plan-output.md 있음 + 모든 TODO 완료 | 새 요구사항으로 전체 재작성 |
| plan-output.md 있음 + 추가 작업 필요 | 기존 계획에 통합하여 업데이트 |
| plan-output.md 없음 | 새로 생성 |

## 2. 작업 타입 자동 감지

요구사항을 분석하여 작업 타입과 최적 워크플로우를 결정하세요:

### 🔥 핫픽스/버그 수정
**키워드**: 버그, 오류, 에러, 수정, fix, bug, error, hotfix, 긴급
**워크플로우**: `분석 → 수정 → 검증`
```markdown
- [ ] analyze-bug-[이슈명]: 버그 원인 분석 및 영향 범위 파악
- [ ] impl-fix-[이슈명]: 버그 수정 구현
- [ ] test-verify-[이슈명]: 수정 사항 검증 및 사이드 이펙트 확인
```

### ➕ 기능 추가
**키워드**: 기능 추가, 새로운, 추가, add, feature, implement, 구현
**워크플로우**: `설계 → 구현 → 테스트`
```markdown
- [ ] design-feature-[기능명]: 기능 설계 및 인터페이스 정의
- [ ] impl-core-[기능명]: 핵심 기능 구현
- [ ] test-integration-[기능명]: 통합 테스트 작성 및 실행
```

### 🏗️ 아키텍처 변경
**키워드**: 아키텍처, 설계, 구조 변경, 리팩토링, architecture, design, refactor
**워크플로우**: `설계 → 문서화 → 단계별 구현 → 검증`
```markdown
- [ ] design-architecture-[변경명]: 아키텍처 설계 및 영향 분석
- [ ] doc-design-[변경명]: 설계 문서 작성 (장기 가치 있는 경우)
- [ ] impl-phase1-[변경명]: 1단계 구현 - [구체적 내용]
- [ ] impl-phase2-[변경명]: 2단계 구현 - [구체적 내용]
- [ ] test-migration-[변경명]: 마이그레이션 및 통합 테스트
```

### 📋 표준/가이드라인
**키워드**: 가이드, 표준, 컨벤션, 스타일, guide, standard, convention, 정책
**워크플로우**: `정의 → 문서화 → 적용 → 검증`
```markdown
- [ ] define-standards-[표준명]: 표준 정의 및 범위 설정
- [ ] doc-standards-[표준명]: 표준 문서 작성
- [ ] impl-apply-[표준명]: 코드베이스에 표준 적용
- [ ] test-compliance-[표준명]: 표준 준수 검증
```

### ♻️ 리팩토링
**키워드**: 최적화, 개선, 리팩토링, refactor, optimize, improve, 성능
**워크플로우**: `현재 상태 보존 → 개선 → 검증`
```markdown
- [ ] test-baseline-[대상명]: 기존 동작 테스트 확보
- [ ] impl-refactor-[대상명]: 리팩토링 실행
- [ ] test-regression-[대상명]: 회귀 테스트 및 성능 비교
```

## 3. TODO 작성 규칙

### ❌ 잘못된 예시
```markdown
- [ ] impl-add-pq-stringarray: pq.StringArray 타입으로 변경 (HIGH)
```
**문제**: 무엇을, 어디서, 왜 변경하는지 알 수 없음

### ✅ 올바른 예시
```markdown
- [ ] impl-add-pq-stringarray: UserService의 tags 필드를 []string에서 pq.StringArray로 변경 - PostgreSQL 배열 타입 직접 지원으로 JSON 변환 오버헤드 제거 (HIGH)
  - 대상 파일: internal/service/user.go, internal/model/user.go
  - 변경 이유: 현재 JSON 인코딩/디코딩으로 인한 성능 저하 해결
  - 예상 영향: 약 30% 쿼리 성능 향상 예상
```

### TODO Context 필수 요소
1. **What**: 구체적으로 무엇을 변경/추가하는가
2. **Where**: 어느 파일/모듈/패키지에 영향을 주는가
3. **Why**: 왜 이 작업이 필요한가
4. **How**: 어떤 방식으로 구현할 것인가 (필요시)
5. **Impact**: 예상되는 영향이나 결과

## 4. 문서 생성 전략

### 장기적 가치 문서 (생성 O)
| 카테고리 | 생성 조건 | 예시 |
|----------|-----------|------|
| **interfaces/** | 외부 시스템 연동, 공개 API | REST API 명세, GraphQL 스키마 |
| **design/** | 핵심 아키텍처, 복잡한 구조 | 마이크로서비스 설계, 이벤트 플로우 |
| **logic/** | 복잡한 비즈니스 규칙 | 가격 계산 로직, 권한 정책 |
| **standards/** | 팀 개발 표준 | 코딩 컨벤션, 보안 가이드 |

### 일회성 문서 (생성 X)
- 단순 버그 수정 분석
- 일회성 마이그레이션 계획
- 특정 버전 대응 문서
- 단순 기능 추가 설명

```markdown
- **예상 소요 시간**: [추정치]
- **영향 범위**: [영향받는 모듈/서비스]

## 핵심 목표
[한 문장으로 해결하려는 문제나 달성하려는 목표 설명]

## 상세 배경
[이 작업이 필요한 이유, 현재 문제점, 기대 효과를 2-3문장으로 설명]

[어떤 기술/패턴/도구를 사용하여 해결할 것인지 간략히 설명]

## 장기 가치 문서 계획
[필요한 경우만 작성]
### [interfaces/design/logic/standards]
- **문서명**: [파일명]
- **목적**: [왜 이 문서가 장기적으로 필요한지]
- **주요 내용**: [포함될 핵심 정보]

## 실행 계획 (TODO)
[작업 타입에 맞는 상세 TODO 목록]

### 진행 현황
- **총 작업**: [N]개
- **완료**: 0개  
- **진행률**: 0%
- **현재 작업**: [첫 번째 TODO] - 대기중

## 위험 요소 및 대응 방안
[예상되는 위험이나 주의사항이 있다면 작성]

## 작업 기록
[act 명령어 실행시 자동 업데이트]
```

## 6. 검증 체크리스트

계획 수립 완료 후 다음 사항을 확인하세요:
- [ ] 모든 TODO가 What/Where/Why를 명확히 포함하는가?
- [ ] 작업 타입이 정확히 감지되었는가?
- [ ] 불필요한 일회성 문서가 포함되지 않았는가?
- [ ] 예상 영향과 기술적 접근이 명시되었는가?
- [ ] 다른 개발자가 읽고 바로 작업할 수 있을 정도로 상세한가?
