1. **순차 실행**: TODO를 순서대로 실행

### 오류 자체 해결 프로세스
```markdown
1. 오류 감지 → 2. 원인 분석 → 3. 해결 방안 수립 → 4. 적용 → 5. 검증
```

#### 자체 해결 예시
| 오류 유형 | 해결 전략 |
|-----------|----------|
| 컴파일 에러 | 타입 수정, import 추가, 문법 교정 |
| 테스트 실패 | 구현 수정, 테스트 케이스 조정, mock 추가 |
| 패키지 없음 | npm install, 대체 패키지, polyfill |
| 권한 오류 | 다른 경로 사용, sudo 시도, 우회 방법 |
| API 실패 | 재시도, timeout 증가, fallback 사용 |

## 🔔 중단 조건 (사용자 개입 필요 시에만)

### 중단이 필요한 경우
1. **중대 결정 사항**
   - 아키텍처 방향성 결정 (예: REST vs GraphQL)
   - 핵심 비즈니스 로직 변경
   - 데이터 구조 근본적 변경
   - 외부 서비스 선택 (예: 결제 시스템)

2. **요구사항 불확실성**
   - 명세서에 없는 기능 동작 방식
   - 모호한 비즈니스 규칙
   - UI/UX 디자인 결정
   - 성능 vs 기능 트레이드오프

3. **제품 사양 질문**
   - 사용자 경험 관련 결정
   - 우선순위가 불명확한 기능
   - 범위(scope) 확인 필요
   - 릴리즈 전략 관련

### 자체 해결하는 경우 (중단하지 않음)
1. **기술적 오류**
   - 컴파일 에러 → 코드 수정으로 해결
   - 테스트 실패 → 구현 수정 또는 테스트 조정
   - 타입 오류 → 타입 정의 수정
   - 린트 오류 → 코드 스타일 조정

2. **의존성 문제**
   - 패키지 설치 실패 → 대체 방법 시도
   - 버전 충돌 → 호환 버전 찾기
   - import 오류 → 경로 수정

3. **인프라 이슈**
   - 파일 권한 → 다른 경로 사용
   - API 연결 실패 → 재시도 또는 mock 사용
   - 환경 변수 누락 → 기본값 사용
