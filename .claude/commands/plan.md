## 2. 영향 범위 분석 (필수)

### 🔍 분석 프로세스

#### 1단계: 직접 변경 대상 식별
```markdown
### 직접 변경 대상
- **파일**: [경로/파일명]
  - 변경 내용: [구체적인 변경사항]
  - 변경 이유: [필요성]
```

#### 2단계: 의존성 체인 추적
```markdown
### 의존성 분석
- **[변경 파일]**
  ├─ imports: [import하는 모듈들]
  ├─ imported by: [이 파일을 import하는 모듈들]
  └─ interface changes: [변경되는 API/인터페이스]
```

#### 3단계: 영향 범위 매트릭스
```markdown
### 영향 범위
| 변경사항 | 영향받는 컴포넌트 | 대응 방안 |
|---------|-----------------|-----------|
| [변경 내용] | [컴포넌트] | [필요한 수정] |
```

## 3. 작업 타입별 접근 방식

### 🐛 버그 수정
**TDD 적용**: ✅ 권장
```markdown
- [ ] test-reproduce-[버그명]: 버그 재현 테스트 작성
- [ ] fix-[버그명]: 최소한의 수정으로 테스트 통과
- [ ] test-edge-cases: 관련 엣지 케이스 추가 (선택)
```

### ➕ 기능 추가
**TDD 적용**: 핵심 로직만 선택적으로
```markdown
# 핵심 비즈니스 로직 (TDD 적용)
- [ ] test-[기능명]-logic: 핵심 로직 테스트 작성
- [ ] impl-[기능명]-logic: 로직 구현

# UI/통합 부분 (TDD 미적용)
- [ ] impl-[기능명]-ui: UI 컴포넌트 구현
- [ ] impl-[기능명]-api: API 엔드포인트 구현
- [ ] test-[기능명]-integration: 통합 테스트 추가
```

### 📝 문서화/표준화
**TDD 적용**: ❌ 미적용
```markdown
- [ ] doc-[문서명]: 문서 작성
- [ ] review-[문서명]: 문서 검토 및 피드백 반영
- [ ] update-related-docs: 관련 문서 일관성 확인
```

### 🏗️ 아키텍처 변경
**TDD 적용**: 기존 테스트 유지하며 리팩토링
```markdown
- [ ] analyze-current-state: 현재 구조 분석 및 문제점 파악
- [ ] design-new-architecture: 새 아키텍처 설계
- [ ] ensure-test-coverage: 기존 기능 테스트 커버리지 확인
- [ ] refactor-step-1: 점진적 리팩토링 (테스트 통과 유지)
- [ ] refactor-step-n: 추가 단계별 리팩토링
```

### 🔧 설정/인프라
**TDD 적용**: ❌ 미적용
```markdown
- [ ] config-[설정명]: 설정 파일 작성/수정
- [ ] verify-[설정명]: 로컬/개발 환경에서 검증
- [ ] deploy-test: 테스트 환경 배포 및 확인
```

## 4. TODO 작성 가이드

### 📌 네이밍 컨벤션
| Prefix | 용도 | 예시 |
|--------|------|------|
| `test-` | 테스트 작성 | `test-payment-calculation` |
| `impl-` | 구현 | `impl-user-service` |
| `fix-` | 버그 수정 | `fix-null-pointer` |
| `refactor-` | 리팩토링 | `refactor-extract-method` |
| `doc-` | 문서화 | `doc-api-guide` |
| `config-` | 설정 | `config-database` |
| `analyze-` | 분석/조사 | `analyze-performance` |

### ✅ TODO 필수 요소
```markdown
- [ ] [prefix]-[작업명]: [무엇을] 한다 (우선순위)
  - 대상: [파일/모듈]
  - 이유: [왜 필요한가]
  - 영향: [예상 결과/영향]
```

## 5. 실용적 문서화 전략

### 문서 생성 기준
| 문서 유형 | 생성 조건 |
|-----------|-----------|
| **API 명세** | 외부 공개 API, 마이크로서비스 간 통신 |
| **아키텍처 설계** | 주요 설계 결정, 복잡한 시스템 구조 |
| **비즈니스 로직** | 복잡한 도메인 규칙, 계산 로직 |
| **개발 가이드** | 팀 표준, 온보딩 문서 |

### 문서화 불필요
- 단순 CRUD 작업
- 일회성 버그 수정
- 자명한 코드 변경
- 임시 해결책
