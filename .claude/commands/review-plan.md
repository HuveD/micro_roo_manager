## 검토 범위

1. **근본 원인 해결 검증**
   - **문제 본질 파악**: 표면적 증상이 아닌 근본 원인을 해결하는지 확인
   - **재발 방지**: 동일 문제가 다시 발생하지 않도록 구조적 해결책 제시
   - **영구적 해결**: 임시방편이 아닌 지속 가능한 해결 방안인지 검증

2. **기존 코드 재사용성 검토**
   - **유사 로직 탐색**: 코드베이스 내 비슷한 기능 구현 여부 확인
   - **공통 모듈화**: 재사용 가능한 컴포넌트/함수 활용 계획
   - **중복 방지**: 새로 작성하려는 코드가 이미 존재하는지 검증
   - **디자인 패턴**: 프로젝트에서 사용 중인 패턴 준수 여부

3. **사이드 이펙트 사전 분석**
   - **영향 범위 예측**: 계획된 변경이 미칠 파급 효과 분석
   - **의존성 체인**: 변경 대상이 사용되는 모든 위치 파악
   - **하위 호환성**: API/인터페이스 변경 시 기존 코드 영향
   - **데이터 영향**: 스키마/데이터 구조 변경의 부작용 예측

4. **계획 완전성 검증**
   - **작업 범위**: 모든 관련 파일/모듈이 계획에 포함되었는지 확인
   - **순차적 의존성**: 작업 순서가 논리적이고 실행 가능한지 검증
   - **테스트 계획**: 변경사항 검증을 위한 테스트 전략 포함 여부
   - **롤백 가능성**: 문제 발생 시 복구 방안 고려 여부

## 작업 타입별 핵심 검증

- **버그 수정**: 근본 원인 해결, 회귀 방지책, 테스트 케이스 추가
- **신규 기능**: 기존 코드 재사용, 아키텍처 일관성, 확장성 고려
- **리팩토링**: 동작 보존 보장, 점진적 접근, 테스트 커버리지
- **성능 개선**: 병목 지점 정확성, 측정 가능한 개선 목표, 부작용 최소화
- **아키텍처 변경**: 마이그레이션 전략, 단계별 실행 계획, 롤백 시나리오
